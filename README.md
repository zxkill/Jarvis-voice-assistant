# Jarvis-Pi — офлайн голосовой ассистент для Raspberry Pi

Jarvis-Pi — русскоязычный офлайн голосовой ассистент и эмоциональный робот. Он работает на Raspberry Pi, поддерживает локальное распознавание речи и синтез и выводит состояние на OLED через ESP32. Все вычисления происходят локально, что обеспечивает приватность и минимальные задержки.

## Возможности

- Активация по фразе «Джарвис» (Vosk)
- Натуральный синтез речи Piper
- Предварительная очистка и нормализация текста для синтеза речи
  (удаление лишних символов, корректное произношение чисел)
- Горячая перезагрузка скиллов
- Система эмоций valence–arousal и проактивные подсказки без пустого small-talk
- Автоматическое определение официальных праздников и выходных (требуется интернет),
  повышение настроения и отправка поздравительных подсказок
- Аналитика отзывов на подсказки и адаптивная политика проактивности
- Проактивные подсказки ждут ответ одну минуту и принимают голосовые и Telegram-реплики без слова «Джарвис»; ответы анализируются простыми эвристиками и могут быть остановлены фразами «закончим общение» или «перейди в режим команд»
- Если команда не распознана ни одним навыком, ассистент вежливо просит: «можете повторить?»
- Параллельная обработка проактивных подсказок не блокирует основную работу устройства
- Асинхронная смена эмоций без блокировки event loop обеспечивает мгновенный отклик
- Чистое завершение по Ctrl+C: обработчик сигналов завершает приложение через `SystemExit` без остановки event loop, предотвращая ошибку `RuntimeError: Event loop stopped before Future completed`
  - История «муд‑профилей»: текущее настроение сохраняется в SQLite
- Визуализация истории настроения с поддержкой работы на сервере без GUI
- Ночная рефлексия: ассистент подводит итоги дня и формирует приоритеты на завтра
- Погодный скилл обновляет настроение и контекст согласно условиям
- Погодный скилл подсказывает одежду и напоминает о зонте
- Календарный скилл сообщает текущую и завтрашнюю дату
- Правильное произношение дат и чисел с учётом русских склонений
- Корректное произношение времени и длительностей для таймеров и статистики
- Знание официальных и ИТ‑праздников
- Ведёт контекст текущих даты и времени, фиксируя каждое обращение пользователя
- Плейбук проактивности в YAML: утренний брифинг, контекстные советы и здоровье без обращений к LLM
- Извлечение дат пользовательских событий и поздравления только перед праздником
- Фильтрация повторяющихся по смыслу подсказок для предотвращения спама
- Дедупликация подсказок по коду события исключает повторные напоминания в течение суток
- Управление через Telegram‑бот
 - Отображение статуса в консоли или на M5Stack Core ESP32 с OLED
- Интеграция с LLM опциональна и может быть полностью отключена
- Локальное хранение краткосрочного и долговременного контекста
- Устойчивое хранение в SQLite с автоматическим восстановлением при блокировках базы данных
- Эпизодическая и семантическая память с поиском по локальным эмбеддингам
- Детекция присутствия и отслеживание лица через камеру
- Автоповорот и обзор камеры при отсутствии пользователя
  - Ночная рефлексия: ежедневный дайджест в формате JSON, приоритеты на завтра и обновление настроения с озвучкой и выводом на экран
  - Устойчивый парсинг JSON для ночной рефлексии: ассистент корректно обрабатывает пустые и лишние ответы, избегая сбоев
- Индикаторы активности камеры и микрофона с требованием явного согласия
- Шифрование чувствительных данных и анонимизация логов

## Поведение и эмоции

Jarvis-Pi сочетает *поведенческое дерево ассистента* на базе `py_trees` и
*эмоциональный ИИ офлайн*. Дерево управляет реакциями на события, а
менеджер эмоций отслеживает координаты `valence`/`arousal`, выбирает пресеты
голоса и отправляет состояние на экран. Компоненты обмениваются сообщениями
через `core.events`: дерево читает флаги из `Blackboard`, а менеджер
реагирует на события камеры, речи и погоды, обновляя настроение.

### Пример `config/affect.yaml`

```yaml
valence_factor: 1.0
arousal_factor: 1.0
ema_alpha: 0.5
announce_mood: false
```

`valence_factor` и `arousal_factor` задают силу влияния внешних событий,
`ema_alpha` сглаживает колебания, а `announce_mood` включает озвучивание
текущего настроения.

### Запуск поведенческого дерева

```python
import time
from behavior.tree import create_behavior_tree
from behavior.integration import setup

setup(start_blink_timer=True)
tree = create_behavior_tree()

while True:
    tree.tick()
    time.sleep(0.1)
```

Эта связка запускает базовое дерево: ассистент приветствует пользователя,
моргает и переходит в ожидание. Дальнейшие узлы и эмоции добавляются по
мере развития системы.

## Настроение ассистента

Эмоциональное состояние хранится в SQLite как структура `{"valence": float, "arousal": float}`. Такой формат облегчает анализ и генерацию ответов.

```python
from memory import db

# Чтение текущего настроения
mood = db.get_mood()
print(mood["valence"], mood["arousal"])

# Частичное обновление значений
db.set_mood({"valence": 0.5})
```

Все операции выполняются через единый API `set_mood`/`get_mood`; устаревшие функции удалены после миграции.

### Сенсоры настроения

Система поддерживает подключаемые **сенсоры настроения**, позволяющие
изменять валентность и возбуждённость в зависимости от внешних факторов.
Базовый класс `MoodSensor` упрощает интеграцию таких источников данных.

```python
from emotion.mood import Mood
from emotion.sensors import TimeOfDayMoodSensor

mood = Mood.load()
sensor = TimeOfDayMoodSensor(mood)
sensor.read_and_update()
```

В комплект входит `TimeOfDayMoodSensor`, повышающий настроение утром и
снижающий вечером. Чтобы создать свой сенсор, унаследуйтесь от
`MoodSensor` и реализуйте метод `measure`, возвращающий дельты настроения.

### Связь настроения и эмоций

После каждого сохранения координат ``valence``/``arousal`` публикуется
событие `mood.changed`. Модуль `EmotionManager` подписан на него и через
политику `emotion.policy` преобразует настроение в дискретную эмоцию.
Событие `emotion_changed` доставляется драйверам отображения и звуков:

- **глаза** на дисплее переключаются на соответствующую иконку;
- **голос** использует выбранный TTS‑пресет;
- **звуковые эффекты** воспроизводятся из палитры, подходящей текущему
  состоянию.

Таким образом, визуальные и аудиосигналы Jarvis отражают реальное
настроение ассистента без дополнительного кода.

### Визуализация настроения

Для отладки и аналитики доступен скрипт `analysis/mood_visualizer.py`,
который строит график настроения по данным таблицы `mood_history`.
График помогает увидеть, как события и взаимодействия влияют на
``valence`` и ``arousal``.

```bash
python -m analysis.mood_visualizer --limit 100 --show
```

Команда откроет окно с историей настроения; для серверов без дисплея
можно сохранить график в PNG:

```bash
python -m analysis.mood_visualizer --outfile mood.png
```

Такая визуализация упрощает аудит эмоциональной модели и повышает
прозрачность поведения ассистента.

Чтобы наблюдать изменения настроения в реальном времени, включите опцию
`watch_mood` в разделе `[ANALYSIS]` файла `config.ini` и запустите
ассистента обычным способом (`python start.py`).  В отдельном окне появится
обновляемый график валентности и возбуждённости.

### Статистика настроения в Telegram

Для быстрой проверки динамики эмоций отправьте своему боту сообщение
«статистика настроения» — в ответ Jarvis пришлёт агрегированную
сводку: количество записей, средние значения валентности и возбуждения
и последние координаты настроения.

## Требования к оборудованию

- Raspberry Pi 4 или новее
- USB‑микрофон и динамик
- Подключение к интернету для Telegram и LLM (опционально)
 - Встроенная или USB‑камера
 - (Необязательно) M5Stack Core ESP32 с OLED — по умолчанию информация выводится в консоль

## Установка

1. Установите Raspberry Pi OS и обновите систему.
2. Клонируйте репозиторий и установите зависимости:

```bash
git clone https://github.com/.../Jarvis-voice-assistant.git
cd Jarvis-voice-assistant
pip install -r requirements.txt
```

3. Скачайте модели Vosk и Piper в каталог `models/`.
4. Заполните `config.ini` и запустите ассистента:

```bash
python start.py
```

## LLM ядро

Модуль `core/llm_engine.py` реализует гибкий слой между ассистентом и
локальным сервером Ollama. Он отправляет запросы к современному эндпоинту
`/v1/chat/completions`, а при его отсутствии переключается на резервный
`/api/generate`, что обеспечивает совместимость со старыми версиями.
Профили `light` и `heavy` позволяют выбирать баланс между скоростью и
качеством, а каждый HTTP‑запрос снабжается заголовком `X-Trace-Id` для
трассировки. Реплики сохраняются в краткосрочную и долговременную память,
что улучшает контекст. Потоковая передача позволяет озвучивать ответы по
мере генерации, сокращая задержку даже при длинных репликах.

### Логирование взаимодействий LLM

Для отладки и анализа контекста ассистент записывает каждое обращение к LLM
в файл `llm_interactions.log`. В журнал попадают готовый prompt с
подставленным контекстом, trace-id и ответ модели. Путь к файлу можно
изменить переменной окружения `LLM_LOG_FILE`. Это облегчает поиск ошибок и
помогает понять, какой контекст получает модель при генерации ответов.

По умолчанию используются модели `llama2` и `llama2:13b`. Их можно
переопределить через переменные окружения `OLLAMA_LIGHT_MODEL` и
`OLLAMA_HEAVY_MODEL`. Если сервер отвечает 404 `model not found`, скачайте
модель командой `ollama pull <имя>` или укажите другое название через
переменные окружения. Подробнее см. [схему взаимодействия модулей](docs/modules_interaction_scheme.md).

## Поведенческое дерево

Ассистент использует **поведенческое дерево** на базе библиотеки `py_trees`.
Этот подход позволяет гибко описывать реакции робота на окружающие события
и расширять их без переписывания основной логики. Дерево создаётся при
запуске `start.py` и регулярно тикует в отдельной `asyncio`‑задаче,
обновляя чёрную доску с текущим состоянием.

Базовая структура дерева включает три ветки:

- приветствие при обнаружении лица,
- моргание для имитации «живости»,
- режим ожидания, когда вокруг тихо.

Каждое действие дерева напрямую обращается к модулю синтеза речи и
драйверу дисплея, а все ошибки выводятся в JSON‑логах. Такой подход
упрощает диагностику и обеспечивает надёжное озвучивание и отображение
состояний, что важно для голосового ассистента.

Поведенческое дерево можно использовать как отправную точку для
создания новых реакций. Запустите ассистента командой:

```bash
python start.py
```

Во время работы значения вроде `face_visible` или `idled` доступны через
глобальную чёрную доску `py_trees` и помогают отлаживать поведение.

### Интеграция событий в Blackboard

Модуль `behavior.integration` связывает событийную шину и чёрную доску.
Он подписывается на `core.events` и автоматически обновляет ключи
`Blackboard`:

- `presence.update` → `face_visible` — фиксирует появление пользователя в кадре;
- `blink.timer` → `should_blink` — запускает моргание по таймеру.

```python
from behavior.integration import setup

# Регистрируем обработчики; при необходимости можно включить встроенный
# таймер моргания: setup(start_blink_timer=True)
setup()
```

Такой подход обеспечивает реактивное поведение и упрощает расширение
дерева за счёт новых событий.

## Переключение дисплея

По умолчанию вывод на «виртуальный экран» отключён, чтобы логи оставались читабельными. При необходимости включите консольный режим, указав в `config.ini`:

```ini
[DISPLAY]
driver = console
```

Для работы с реальным M5Stack Core ESP32 задайте:

```ini
[DISPLAY]
driver = serial
```

После этого прошейте и подключите устройство:

```bash
cd JarvisM5
pio run -t upload
```

## Автосканирование камеры

Если в кадре долго нет лица, ассистент включает плавное **автосканирование камеры** и затем «засыпает». Чтобы функция работала, активируйте модуль присутствия в `config.ini`:

```ini
[PRESENCE]
enabled = true
```

Камера поочерёдно оглядывает комнату, а появившийся человек или голосовая команда моментально возвращают её в рабочий режим.
При первом запуске модуль автоматически выдаёт согласие на использование камеры и показывает окно предпросмотра, что упрощает проверку детекции лица.

## Конфиденциальность и безопасность

- Все обращения к камере и микрофону требуют явного согласия пользователя, а индикаторы активности выводятся на экран.
- В таблицах SQLite конфиденциальные поля (например, ``payload``) шифруются ключом из переменной окружения ``JARVIS_DB_KEY``.
- Ключ можно сгенерировать командой ``python -c 'from cryptography.fernet import Fernet;print(Fernet.generate_key().decode())'``.
- Персональные данные в логах автоматически маскируются.
- В `config.ini` добавлена секция `[PRIVACY]` с настройками «тихих часов» и лимитом дневных инициатив ассистента.

Дополнительные рекомендации описаны в [политиках безопасности](docs/security_policies.md).


Скилл подхватится автоматически после перезапуска.

## Долговременная память

Jarvis ведёт две разновидности памяти:

- **Эпизодическая память** — хранит отдельные события дня и системные
  логи.
- **Семантическая память** — аккумулирует устойчивые факты и знания.

Обе таблицы индексируются локальными эмбеддингами, что позволяет
находить похожие записи по смыслу без обращения к внешним сервисам.
Используйте функции `store_event()`, `store_fact()` и
`retrieve_similar()` из пакета `memory`, чтобы сохранять информацию и
восстанавливать её при необходимости. База данных SQLite создаётся
автоматически и не требует ручной настройки.

### События дня

Ежедневные заметки целиком хранятся в таблице ``episodic_memory``.
Метки каждого события дополнительно записываются в вспомогательную
таблицу ``event_labels`` SQLite, по столбцу ``label`` создан индекс.
Благодаря этому выборка по метке выполняется одним SQL-запросом без
перебора всей таблицы, что ускоряет работу на больших объёмах данных.
Пример:

```python
from context.long_term import add_daily_event, get_events_by_label

# Сохраняем событие с метками
add_daily_event("прогулка в парке", ["отдых", "спорт"])

# Получаем все события, помеченные как "спорт"
print(get_events_by_label("спорт"))
# ['прогулка в парке']
```

Такой механизм делает Jarvis пригодным для долгосрочного
использования: ассистент запоминает «эпизоды» и может напоминать о них
спустя время, что повышает вовлечённость и пригодность проекта для
реальных сценариев умного дома и личной продуктивности.

Модуль `core/llm_engine` при выполнении функций `think` и `act`
автоматически расширяет контекст за счёт семантического поиска:
`retrieve_similar()` выбирает релевантные фрагменты, и они подставляются
в шаблоны LLM через параметр `{long_context}`. Благодаря этому ассистент
учитывает прошлый опыт и отвечает осмысленнее. Чтобы улучшить качество
результата, заранее наполните память ключевыми фактами и событиями.

### Предпочтения пользователя

Jarvis умеет сохранять индивидуальные предпочтения, например:
```
запомни, что я не ем хлеб
```
Команда обрабатывается встроенным навыком `intel_status` и записывает фразу в
семантическую память. Извлечённые предпочтения автоматически
подмешиваются в функции `think()` и `act()`, помогая ассистенту давать
более точные и персонализированные ответы. Для программного доступа
используйте функции `memory.preferences.save_preference()` и
`memory.preferences.load_preferences()`.

### Навык `intel_status`

Этот встроенный скилл голосового ассистента Jarvis отвечает за ведение
краткого пользовательского контекста и отчёт о нём.  Команда вида
``запомни ...`` позволяет добавить заметку, а запрос
``что ты запомнил`` возвращает последние записи.

В таблице `context_items` БД такие данные сохраняются с ключами,
начинающимися с префикса `user:`.  Значение хранится в формате JSON,
где поле `text` содержит саму фразу пользователя.  При извлечении
функция `_get_last_context_items` игнорирует чужие записи и ведёт лог
с количеством отфильтрованных элементов, что упрощает отладку и
мониторинг.

Для выбора метода построения эмбеддингов в `config.ini` добавлена секция
`[EMBEDDINGS]`. Значение `profile` может быть `simple` (по умолчанию)
для быстрого хеширования или `transformer` для использования локальной
модели `sentence-transformers`.

## Дневные дайджесты

Каждый вечер Jarvis подводит итоги дня и сохраняет их в таблицу
`daily_digest`. Это помогает отслеживать прогресс и настроение. Получить
последний дайджест или перечень записей можно через модуль
`memory.db`:

```python
from memory import db

# Сохранить новый дайджест
db.add_daily_digest("день прошёл продуктивно", "закончить отчёт", 8)

# Вывести последний дайджест
print(db.get_last_digest()["digest"])

# Показать дайджесты за неделю
for item in db.list_digests(limit=7):
    print(item["ts"], item["digest"])

# Очистить записи старше месяца
db.cleanup_old_digests()
```

По умолчанию асcистент хранит дайджесты только за последние **30 дней** и
не более **100 записей**. Ротация выполняется автоматически при каждом
подключении к SQLite, что предотвращает рост файла базы данных. При
желании параметры политики хранения можно изменить:

```python
db.cleanup_old_digests(retention_days=60, max_count=200)
```

Такой подход облегчает администрирование и ускоряет запросы, сохраняя при
этом полезную историю взаимодействий.

## Проактивность

Файл `proactive/playbook.yaml` описывает утренние брифинги, контекстные
подсказки и напоминания о здоровье. Все они динамически формируются LLM,
поэтому текст легко адаптируется под пользователя. Добавляйте собственные
триггеры и реплики, чтобы ассистент реагировал на изменения окружения и
сам предлагал действия. Планировщик запускает сценарии по времени,
событиям и состоянию присутствия пользователя.

Генерация текстовых подсказок выполняется в отдельном потоке,
поэтому даже при долгих запросах к LLM камера и остальные
подсистемы продолжают работать без зависаний.
Фоновые потоки регистрируются в менеджере остановки, благодаря чему
завершение ассистента по Ctrl+C происходит мгновенно и без ошибок.

Каждая подсказка перед отправкой сохраняется в SQLite и получает
уникальный `suggestion_id`. Это позволяет фиксировать ответы пользователя
и корректировать политику проактивности. Чтобы избежать спама, действует
минимальный интервал в одну минуту между подсказками, который адаптивно
увеличивается или уменьшается в зависимости от принятия рекомендаций.
Дополнительно подсказки помечаются уникальным кодом `reason_code`, и
повторное событие с тем же кодом в течение суток игнорируется.

Собранные в таблице `suggestion_feedback` отзывы анализируются, и
ассистент рассчитывает долю принятых и отклонённых подсказок. На основе
этой метрики политика проактивности автоматически подстраивает
минимальный интервал между подсказками и дневной лимит, делая советы
менее навязчивыми при частых отказах и более активными при высоком
одобрении.

### Диагностика проактивности

Если подсказки перестали приходить, проверьте внутренние счётчики
политики: `policy.daily_limit_reached`, `policy.throttled` и
`policy.cancelled_keyword`. Они помогут понять, была ли подсказка
отклонена из‑за превышения дневного лимита, слишком частых отправок или
неподходящих ключевых слов. Узнать значения можно так:

```python
from core.metrics import get_metric

print(get_metric("policy.daily_limit_reached"))
```

Высокие значения сигнализируют о причинах блокировки проактивности и
позволяют оперативно скорректировать конфигурацию.

## Ночная рефлексия

В течение дня Jarvis конспектирует все важные диалоги: после каждого
ответа создаётся краткое резюме с тематической меткой, которое
сохраняется во временной «дневной памяти». Ночью эти заметки
агрегируются, из них извлекаются ключевые факты, которые затем
переносятся в долговременный контекст, а дневной буфер очищается.

Каждую ночь ассистент формирует «Дайджест дня»: с помощью локальной LLM
подводятся итоги, фиксируются приоритеты на завтра и обновляется уровень
настроения. Результат возвращается в формате JSON с полями ``digest``,
``priorities`` и ``mood`` — это упрощает дальнейшую обработку. Данные
сохраняются в SQLite и отправляются пользователю через проактивные
уведомления.

Если модель возвращает лишний текст или пустой ответ, Jarvis пытается
выделить JSON-блок и подставляет безопасные значения.  Такой устойчивый
парсинг предотвращает сбои ночной задачи и делает ассистента надёжнее.

## Озвучивание настроения

Параметр `announce_mood` в файле `config/affect.yaml` управляет голосовым
сообщением о текущем состоянии эмоций. Установите значение `false`, если
нужно отключить озвучивание «муд‑профиля» и оставить обновление настроения
только во внутреннем логе.

## Служебные команды

В комплекте есть «служебный» скилл `maintenance`, который помогает
обслуживать память ассистента и ускорять проверку функционала. Он умеет:

- очищать дневную, эпизодическую и семантическую память, а также дневные
  дайджесты;
- принудительно запускать ночную рефлексию и агрегацию данных.

Например, скажите «очисти дневную память», «запусти рефлексию» или
«агрегируй данные», чтобы моментально удалить временные записи либо
сформировать дайджест дня без ожидания полуночи. Если при рефлексии
произойдёт ошибка, ассистент уведомит об этом голосом, а детали можно
посмотреть в логах.

## Запуск в Docker

Ассистент можно развернуть на любой машине, где установлен Docker и
docker-compose. Репозиторий содержит `Dockerfile` и `docker-compose.yml`,
которые автоматически поднимают Jarvis, Loki и Grafana.

```bash
# первый запуск: устанавливаем зависимости и собираем базовый образ
docker compose up --build

# последующие перезапуски без пересборки образа
docker compose up
```

Исходный код монтируется в контейнер как том, поэтому после правок в файлах
достаточно перезапустить сервис без пересборки. Это ускоряет разработку и
исключает простои.

После запуска:

- Jarvis доступен внутри контейнера и сразу начинает слушать команды;
- Grafana открывается на <http://localhost:3000> (логин/пароль по умолчанию
  `admin/admin`);
- Логи ассистента автоматически отправляются в Loki и могут
  просматриваться через интерфейс Grafana по уровням и тегам.

Остановка стека выполняется стандартной комбинацией `Ctrl+C` или командой

```bash
docker compose down
```

Перед запуском скопируйте файл окружения и при необходимости отредактируйте
его параметры:

```bash
cp .env.example .env
```
